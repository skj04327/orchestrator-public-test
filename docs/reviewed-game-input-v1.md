# 검토 확인값을 사용하는 게임 실행 입력

비공개 `main`에 AI 도구 설정이 포함되면 기본 디스크 수집은 실행 입력을 차단한다. 메타데이터 사전 점검은 소스 blob을 받기 전에 어떤 선택지가 가능한지 알려 준다.

```sh
node scripts/disk-baseline-cli.mjs preflight
node scripts/disk-baseline-cli.mjs capture-projected <새_비공개_저장소_경로> <projectionSha256>
node scripts/disk-baseline-cli.mjs status <비공개_저장소_경로> <baseSha>
```

`preflight`는 비공개 저장소와 main을 확인하고 Git 트리 해시를 검증한다. 일부 파일을 제외할 수 있으면 `projection-available`, 제외 파일 수, 커밋과 확인값을 반환한다. 실행 담당자는 비공개 GitHub의 해당 커밋에서 제외 대상을 확인한 후 별도 저장 경로에 수집할 때 확인값을 명시한다. 도구는 출력에 제외 파일명이나 내용을 쓰지 않는다. 확인값은 특정 커밋·트리·정책·제외 목록의 일치 여부를 고정하는 해시다. 사용자의 서명이나 게시 권한을 제공하지 않는다.

제외 후보는 루트 `.claude`, `.codex`, `.gemini` 디렉터리에 바로 속한 비실행 일반 파일이다. 최대 8개이며 각각 64KiB 이하다. 다른 경로 위반이나 같은 바이트를 공유하는 유지 파일이 있으면 이 경로도 차단된다. Git 트리가 움직이거나 확인값이 다르면 받아들이지 않는다. 제외 대상은 blob 요청, 실행 아카이브, 의존성 준비에서 빠진다. 나머지 파일은 기존 해시·크기 검증을 거쳐 모두 보존한다.

해당 실행 입력은 별도 수집 프로필을 사용한다. 보관용 디렉터리와 별도 경로를 지정한다. 같은 커밋의 캐시가 지정 경로에 있으면 기존 수집 유형을 확인하고 유형이 다른 캐시는 파일을 읽기 전에 거절한다. 캐시 유형 검사는 커밋별로 적용된다. 보관 전용 캐시는 실행 입력이 될 수 없다. 기본 전체 입력 수집은 기존 차단 기준을 적용한다.

대용량 검사 및 비공개 보고서에는 `github-main-projected` 바인딩과 제외한 파일 수, 정책, 확인값이 기록된다. 보고에 포함된 파일 수와 바이트는 검사에 공급한 부분만 가리킨다. 작은 메모리 검사기는 이 프로필을 받지 않는다. 검사 결과는 해당 입력과 후보 변경에 적용된다. 독립 리뷰와 게시 승인 단계는 별도다.

실제 비공개 main에서 원격 메타데이터 사전 점검 결과를 확인했다. 합성 설정 파일로 CLI, 새 입력 수집, 오프라인 의존성, 여섯 단계 Docker 검사와 상태 읽기를 검증한다. 실제 게임의 실행용 자료 수집과 lockfile에 맞는 tarball 확보는 후속 작업이다.

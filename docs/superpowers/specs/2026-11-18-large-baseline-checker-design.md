# Large baseline checker design

User authorizes continued native implementation in small independent units, without design approval pauses. This unit adds a host API for one fixed baseline npm stage on a checks-purpose disk snapshot; it does not claim a complete task validator or publishing authority.

Use the existing fixed Git inventory, opaque disk capability and trusted Docker host. Keep the old 32MiB bridge unchanged. A new one-shot async tar producer uses flat SHA blob names and a bounded metadata manifest, rechecking private permissions/size/Git SHA1/SHA256 while reading <=64KiB chunks. Never extract archives on the host. Reject data-only/copied handles before creating Docker resources. Reject Actions and untrusted image IDs. No model input controls commands, mounts or resource settings.

Approaches considered: enlarging the old base64 payload would amplify memory and weaken its limit; bind-mounting a mutable cache would expose extra host state and create cross-stage mutation concerns. Chosen here: stream verified regular files through docker cp into a fresh input volume, mount readonly, and copy into a fresh bounded checker workspace. Source identity and integrity are host observations, not model claims or signed publication approval.

Checker: fresh container per stage; fixed npm ci --offline --no-audit --no-fund followed by exactly typecheck, unit-test (npm test -- --reporter=dot), or build. No network, tokens, provider config, Docker socket, automatic pulls or skipped installation scripts. UID1000, readonly root/input, cap-drop ALL, no-new-privileges, PID128, CPU2, memory/swap3GiB, /work tmpfs2GiB and /tmp128MiB. Existing local pinned image only; it has no actual game dependency cache. Fail honestly if offline dependencies or resources are insufficient. Report only fixed failure kind/exit/status/time/source binding; publishAuthorized always false. No queue activation, candidate integration, persistent approval or actual private-source execution in this unit.

Seed container is never started, holds only the new volume, has no network and uses resource limits. All ambiguous creates must clean up, including interrupted archive production. Await child exit and input reader shutdown before accepting transfer or cleanup completion. Confirm final source transfer digests before starting project code. Container/volume removal is part of successful observation; cleanup uncertainty throws.

Validation uses synthetic Git-generated Unicode/executable assets and a >32MiB binary, actual isolated Docker/npm, explicit data-only/copied handle denial, tamper/abort/input-consumer failure, readonly/input credentials attacks, timeout/output cleanup and fail-closed offline cache miss. Existing general/full Docker checks remain required. Private full-tree archival cache is never used. Follow-on: candidate/sequential six-stage report integration, dependency provenance/cache, safe actual execution input policy and real game baseline checks.

# Large disk candidate validation design

Continue native implementation from Draft17/localba92cca under the user's standing autonomous-development authorization. Keep data-only caches permanently non-executable, default sensitive-path policy and old32MiB bridge unchanged. Actual private game/model execution and dependency runtime preparation remain out of scope.

Goal: safely validate the existing encrypted local worker's small allowlisted candidate against an eligible full disk baseline, in six fresh isolated npm stages, then append a private terminal report using the existing one-shot independent claim. Success remains checks-passed-awaiting-review with review=not-run and publishAuthorized=false.

Approaches: raising the memory bound would weaken the old bridge; replacing the baseline tar in-place could bypass verified-source provenance. Choose an independent small immutable overlay, copied separately into a readonly input volume with distinct names, over the unchanged verified full baseline. Preserve every asset/mode, reject replacing existing tests, path collisions and combined disk capacity overflow. Candidate is captured synchronously from validated decrypted bundle into opaque host state; copied/forged/data-only handles fail before claim/Docker.

Reuse the fixed resource-bounded Docker runner, command map and shared completion engine. Baseline/candidate each run npm ci --offline --no-audit --no-fund then original typecheck, full unit tests, build in fresh containers. Candidate overlay never changes package/lock/config or existing tests. Do not accept caller-provided runner/commands. Baseline transfer rehashes all blobs on every stage. Host checks source/artifact identity before claim and after execution.

Add strict schema2 disk-v1 claim/report with baselineManifestSha256 (not pretending it is the old whole-content digest), pinned repository/main/tree/counts/time and candidate digest. Share the same exclusive independent-claim/report paths with schema1 to prevent competing profiles or retries. Keep all valid schema1 reports supported and validate both profiles strictly via the existing status API/CLI. Reports contain metadata only; no raw source/output/keys. Infrastructure errors stop further stages; game command failures still compare all six and never pass. Abort/cleanup failures remain non-publishable needs-recovery. No retry or signed publishing authorization.

Tests use synthetic Git40MiB Unicode assets and actual network-none Docker. Assert six-stage lifecycle mapping and full unit-test arguments separately (close PR17's minor), fresh source, candidate bytes frozen, new tests allowed/existing tests refused, forbidden paths/collisions/capacity, failure comparison and immutable claims, malformed/tampered schema2, cancellation/artifact mismatch and denial before resources. Public CI uses only synthetic data and is run once per tested pushed snapshot. Then commit/push/new Draft based on feature/large-baseline-checker-v1, verify changed blobs and CI, save next checkpoint.

# Protected worker/exporter implementation plan

Goal: implement the next boundary from PR #9 without enabling live subscription execution.
Spec/authority: user handoff Phase 1 and docs/phase-0-1-handoff-2026-11-16.md, section on protected worker/exporter. The user explicitly asked to continue implementation and Draft PR delivery.

Architecture: Docker worker with non-root user, read-only rootfs, capability drop, no-new-privileges, bounded memory/CPU/PIDs/time/output. No host binds, Docker socket, Actions credentials/control paths, or exporter key are passed. Inputs/trusted scripts are copied before start, worker writes only a disposable named volume. After attached execution, independently verify the container is stopped, capture bounded regular files via strict tar parsing (never extract an untrusted archive), remove container and volume, then host-owned code validates and encrypts in memory to an exclusive host output. No untrusted process can write that output. Raw output is bounded and discarded from public logs. Actual CLI/tool/runtime policy and validation attestation remain separate blockers.

Alternative: process/env filtering on the host leaves background writers and /proc access; bind-mounting the whole repo exposes exporter/control paths. Choose a container with no host mounts. The live constant false gate stays in place even after fixture attacks pass; subscription policy, provider network/auth restrictions and trusted validation are still unresolved.

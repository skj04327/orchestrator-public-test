# 검증된 디스크 기준 스냅샷 v1

Phase 1의 대용량 전달 단위다. 기존 32MiB 메모리 수집기와 검사기를 유지하면서, 전체 Git 파일을 호스트의 비공개 디스크에 순차 바이트 스트림으로 받는 별도 프로필을 추가한다. 수집 완료와 게임 검증 완료는 서로 다른 상태다.

## 실제 기능

기존 private-main 조회·Git 트리 재구성·파일 크기 검사를 공통 모듈로 공유한다. 대상 저장소·main·GET 경로는 고정이다. raw blob API의 SHA 주소를 사용하므로 소스 파일 이름이 셸 명령이나 다운로드 URL이 되지 않는다. 토큰은 gh 자식에만 전달하고 코드 검사나 소스에 전달하지 않는다. Git 파일은 호스트에서 실행하지 않는다.

raw 전송은 stdout을 문자열/전체 Buffer로 모으지 않고 파일 쓰기에 맞춰 읽는다. 정확한 크기와 Git SHA-1·SHA-256을 증가식으로 검사한다. 초과·부족·변조·오류 출력 과다·시간 초과·취소 시 자식을 종료하고 직접 만든 부분 파일만 제거한다. 기존 파일/링크를 덮어쓰지 않는다. 프로세스의 출력과 원시 오류는 공개 로그에 전달하지 않는다.

디스크 프로필은 전체 논리 소스 1GiB, 파일당 128MiB, 10,000파일, 최대 4,000번의 요청, 동시 raw 전송 3개, 전체 30분과 개별 전송 3분 한도다. 파일 전송 중 컨트롤러가 다루는 청크도 제한한다. 외부 gh 구현 전체의 메모리 사용량을 이 숫자로 보증하지 않는다. 중복 blob은 한 번만 저장한다. 예상 디스크 데이터와 64MiB 여유 공간을 확보할 수 없으면 받기 전에 차단한다. 별도 유료 자원·요청 재시도·데이터 생략은 없다.

기본 실행 입력용 디스크 경로는 안전한 Unicode 문자·숫자와 일부 파일 이름 문자를 허용하되 탈출·제어 문자·인증/캐시 디렉터리는 거부한다. 기존 메모리 경로의 ASCII/파일/합계 한도는 바꾸지 않는다. Git의 일반/실행 모드와 전체 디렉터리 트리, 각 blob 해시를 인덱스에 보존한다. Git LFS 실제 데이터나 특수 파일을 해석하는 기능은 아니다.

별도 `capture-data`는 전체 자료의 호스트 보관만 허용하는 data-only 목적이다. 인증 경로도 원래 이름이 아닌 SHA blob 파일로 로컬 비공개 저장할 수 있지만, 이 목적은 실행 입력으로 승격되지 않는다. 작은 자료여도 materialize/독립 검사 연결에서 blocked-input-policy로 거부한다. 기본 수집이 차단됐다고 자동으로 이 모드로 전환하지 않는다. 동일 커밋의 다른 목적 캐시는 혼용하지 않는다. 암호화 저장소나 비밀 탐지기를 구현한 것은 아니며, 원본 데이터는 0700/0600 호스트 파일로 보관한다. 보관 전용 데이터를 AI·컨테이너·게시기에 제공하지 않는다.

## 저장과 다시 열기

저장 루트는 Git 밖의 신뢰할 수 있는 Unix 경로이고 0700, 파일은 0600이다. 소스는 원래 경로 대신 SHA 이름의 blob 객체로 저장한다. 임시 디렉터리에서 모든 전송·검증을 끝내고 main/비공개 여부를 재확인한 뒤 인덱스 hardlink를 배타적으로 마지막에 생성한다. 부분 상태는 유효한 스냅샷이 아니다. 실패 시 진행 중인 모든 파일 작성자가 종료한 뒤 자신이 만든 임시 디렉터리를 지운다.

기존 캐시를 열 때에는 전체 트리·인덱스·개별 파일의 소유자/권한/크기/유형·SHA를 다시 확인한다. 심볼릭 링크와 일반 blob의 hardlink, 누락·변조를 거부한다. 캐시가 원래 관찰한 main 정보는 역사적 관찰이며 현재 main 확인이나 서명된 게시 승인을 대신하지 않는다. 캐시 파일을 임의 변경할 수 있는 동일 호스트 사용자 프로세스는 신뢰 경계 밖이다.

진행 claim은 자동 만료하지 않는다. 실패·SIGKILL 뒤 완료 인덱스 없이 claim만 남으면 running-or-needs-recovery로 표시하고 자동 재다운로드하지 않는다. 전원 장애 복구·실패 캐시 자동 수리·안전한 복구 명령은 후속 작업이다. 상태 조회도 파일 무결성을 다시 읽으므로 대용량 캐시에서는 시간이 든다.

```sh
node scripts/disk-baseline-cli.mjs capture <private-root-outside-git>
node scripts/disk-baseline-cli.mjs capture-data <separate-private-data-root>
node scripts/disk-baseline-cli.mjs status <private-root-outside-git> <commit-sha>
```

CLI는 로컬 capture/capture-data/status만 지원하며 Actions·임의 실행·추가 인자를 거부한다. 출력은 상태와 커밋·파일 수·크기 등 메타데이터뿐이고 원본 경로·바이트·인증정보는 출력하지 않는다. 비공개 게임 데이터를 받는 경로는 공개 CI에서 실행하지 않는다. 테스트에서는 합성 프로토콜만 로컬 호스트로 모사한다.

## 기존 검사기 연결 범위

작고 호환되는 캐시는 `materializeDiskBaseline()`과 `runDiskIndependentChecks()`로 기존 여섯 격리 검사에 연결한다. 객체를 복사하거나 JSON을 직접 만들어도 신뢰된 스냅샷이 되지 않는다. 다시 읽은 바이트를 검증하고 main 출처와 SHA-256을 보고서에 보존한다.

실행 입력 목적이어도 32MiB 합계·1MiB 파일 또는 기존 경로 정책을 넘으면 blocked-checker-capacity로 남기고 독립 실행 claim을 만들지 않는다. data-only는 크기에 관계없이 blocked-input-policy다. 큰 애셋을 복사할 검사 작업 공간과 오프라인 의존성 환경은 아직 별도 작업이다. 어떤 결과도 AI 리뷰 완료나 게시 가능으로 바꾸지 않는다. ai 명령의 큐 접수 뒤 자동 실행도 아직 열지 않는다.

## 검증과 후속 작업

합성 40MiB 바이트 스트림으로 이전 메모리 한도를 넘는 전송과 해시·파일 권한을 확인한다. 변조·길이·오류 출력·시간 초과·취소·기존 대상 보존, 캐시 중복 제거·인덱스 커밋·재열기·링크/인증 경로 거부와 실제 Docker 검사 연결을 시험한다. 합성 시험은 실제 게임 검사가 통과했다는 증거가 아니다.

다음은 큰 디스크 스냅샷을 메모리 직렬화 없이 전달하는 제한된 검사 작업 공간과 검증된 오프라인 의존성 캐시다. 그 뒤 실제 게임 기준 타입 검사·전체 테스트·빌드를 수행해야 한다. 실제 구독 AI·독립 모델 리뷰·분리 게시기·모바일 배포·병합은 이번에 수행하지 않는다.


## 이번 단위의 실제 검증 기록

2026-11-17 로컬 최종 일반 테스트 119/119, 실제 Docker 합성 테스트 10/10이 통과했다(실패·건너뜀 0). Docker는 기존 로컬 이미지 ID를 사용했고 네트워크를 차단했다. 작은 디스크 스냅샷에 대해 기준/변경 각각 타입 검사·전체 테스트·빌드 여섯 명령을 실제 실행하고 main 출처와 게시 불허 상태를 확인했다. JavaScript·Bash 구문, YAML 파싱과 diff 검사도 통과했다.

별도 읽기 전용 리뷰에서 Critical/Important 결함은 발견되지 않았다. 리뷰 후 CI 경로 필터와 동시 작성자 취소·캐시 트리 변경·main 이동·hardlink/권한 회귀 검증을 보강했다. 기존 캐시의 누락 blob을 새 수집으로 오인하는 문제, 목적 변경이 manifest에 결합되지 않은 문제, fsync 중 취소 누락은 실패를 재현한 뒤 수정했다.

실제 비공개 저장소의 전체 자료는 명시적인 data-only 목적에서 호스트 비공개 디스크로 수집 완료했다. 재열기로 모든 blob을 다시 해시 검사했고 실행 입력 변환이 blocked-input-policy로 거부되는 것을 확인했다. 실제 커밋·원본 경로·내용·세부 목록·캐시 위치는 공개 문서나 CI에 포함하지 않는다. 실행용 기본 정책을 완화하지 않았고 게임 코드·모델을 실행하지 않았다. 캐시는 로컬 일반 파일이며 암호화나 백업·전원 장애 복구를 보증하지 않는다.

인수인계: 다음 개발자는 최신 Draft와 로컬 변경을 먼저 대조한다. 호스트의 `/tmp/orchestrator-private-data-location.json`(0600)에 기존 보관 전용 캐시 위치가 있고 `/tmp/orchestrator-private-data-result.json` 및 `/tmp/orchestrator-private-data-reopen-result.json`에 비공개 검증 근거가 있다. 이 파일을 공개 Git에 추가하거나 전체 출력하지 않는다. 실행용 입력은 별도로 허용 정책을 설계해야 하며 보관 전용 캐시는 재사용하여 실행하지 않는다. 임시 작업 공간이 보존되지 않은 경우 캐시가 있다고 가정하지 않는다.

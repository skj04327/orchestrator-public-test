# 비공개 main 고정 기준 수집 v1

Phase 1 후속 단위. PR #14의 직접 제공 기준 입력에 더해, 실제 비공개 저장소의 main을 읽기 전용으로 고정하는 경로를 추가한다. 검증을 통과한 작은 전체 스냅샷만 독립 검사기에 전달하며 게시 승인은 항상 false다.

## 수집과 검증

대상은 코드에 고정한 비공개 게임 저장소와 refs/heads/main이다. 기존 gh 인증으로 GET만 수행한다. 토큰을 추가 발급·저장하거나 AI/검사 컨테이너에 전달하지 않는다. CLI/API 메타데이터에 저장소가 private이며 정확한 full_name인지 확인한 뒤 main 커밋, 해당 커밋의 root tree, 잘리지 않은 전체 recursive tree를 읽는다.

모든 부모 디렉터리·유형·모드·중복·크기를 검증하고 Git의 이름 정렬과 tree 객체 형식으로 각 하위 트리와 root의 SHA-1을 재구성한다. 심볼릭 링크·서브모듈·특수 항목, 누락·잘린 트리, 바뀐 해시는 거부한다. 일반 파일/실행 파일의 blob 바이트를 보존하지만 기존 검사기의 파일 모드 재현 제한은 유지된다. GitHub가 인증된 읽기 경로에서 알려준 main→commit→tree 관계를 신뢰하며, Git commit 서명 자체를 검증하는 기능은 아니다.

이후 전체 트리가 기존 10,000파일 / 32MiB 합계 / 1MiB 파일 한도 안인지 확인한다. 초과 시 blocked-capacity로 반환하고 blob을 하나도 받지 않는다. 자격증명·캐시 경로 등 기존 입력 정책을 어기거나 npm 잠금 프로젝트가 아니면 blocked-input-policy로 막는다. 큰 애셋을 임의 제외하거나 일부 경로만 받아 전체 기준으로 표시하지 않는다.

허용된 트리의 blob만 SHA로 읽고 정규 base64·크기·Git blob SHA-1을 확인한다. 같은 blob은 재사용한다. 마지막에 저장소 비공개 여부와 main SHA를 다시 확인한다. 커밋이 움직였으면 거부하며, 새 기준으로 자동 재시도하지 않는다. 수집은 최대 180초·10,006 GET, 각 gh 호출은 30초·출력/오류 합계 4,000,000바이트다. 실패·속도 제한을 유료 경로나 무제한 재시도로 우회하지 않는다.

Git SHA-1은 Git 객체와의 일치를 검사한다. 독립 검사용 SHA-256은 실제 전체 파일 바이트를 별도로 묶는다. 출처 증거는 저장소·main ref·커밋·tree·파일 수·전체 크기·SHA-256·호스트 관찰 시각이다. 수집 시점의 main임을 나타내며 미래 게시 시점의 최신 main 확인을 대체하지 않는다.

## 실행과 상태

```sh
node scripts/pinned-baseline-cli.mjs inspect
```

출력은 상태·파일 수·전체 크기·publishAuthorized:false뿐이다. 소스·파일 경로·인증정보를 출력하지 않는다. CLI는 로컬 inspect만 지원하고 Actions·추가 인자·다른 호스트/저장소/브랜치를 거부한다. 실제 blob은 호스트 메모리에만 캡처하며 Git 체크아웃이나 공개 파일을 만들지 않는다.

신뢰하는 호스트 코드는 `runPinnedIndependentChecks({id,stateRoot,privateKey,imageId,...limits})`로 연결한다. 이미 받은 작업 결과의 커밋과 실제 main이 다르면 blob을 받기 전에 거부한다. 한도 안이면 기존 네트워크 없는 여섯 검사로 연결한다. `get` 대체 인자는 테스트/검토된 호스트 어댑터용이며 모델이나 MCP가 임의 엔드포인트를 정하는 권한이 아니다.

수집된 기준 객체는 깊게 동결하고 호스트 내부 WeakMap과 연결한다. 직접 만든 기준 입력 JSON·복사한 기준·사용자 지정 플래그는 고정 출처로 태그되지 않는다. 새 보고서는 baselineBinding:github-main-pinned와 baselineProvenance를 비공개 claim/report에 묶는다. 기존 caller-supplied 보고서와 입력 경로는 계속 지원한다. 출처 증거와 보고서의 커밋·내용 지문이 달라지면 오류다. 호스트 파일을 임의 수정하는 동일 사용자 프로세스는 신뢰 경계 밖이며 이 증거는 서명된 게시 승인서가 아니다.

blocked-capacity/policy는 검사를 시작하지 않으므로 독립 실행 claim을 만들지 않는다. 반환 상태를 운영자가 확인해야 하며 자동 재시도하지 않는다. 검사/원시 실패 진단/복구 UI/서명된 별도 게시기는 기존 미완료 상태다. 모든 결과는 review:not-run, publishAuthorized:false다.

## 실제 점검과 제한

2026-11-17 실제 비공개 main에서 메타데이터 GET과 새 CLI를 시험했다. 전체 트리 무결성 판정 후 기존 입력 한도를 넘겨 blocked-capacity로 차단됐다. blob을 받거나 게임 코드·타입 검사·단위 테스트·빌드를 실행하지 않았다. 실제 파일 경로·커밋·크기 상세·원시 응답은 공개 저장소에 넣지 않는다.

이것은 게임 기준 검사가 통과했다는 뜻이 아니다. 다음 우선 작업은 큰 정적 애셋을 보존하며 전부 메모리에 올리지 않는 디스크/읽기 전용 볼륨 전달과 오프라인 의존성 런타임이다. 현재 512MiB 작업 tmpfs와 전체 입력 한도를 무작정 넓히지 않는다. LFS 실제 데이터 해석과 다른 파일 모드·테스트 배치도 별도 검토가 필요하다.

PR #14에서 남긴 실패 메타데이터 모순도 이번에 강화했다. check_failed/exitCode:0, 인프라 실패를 checks-failed로 표시한 보고서, null/원시값 상태 파일을 거부한다. 정상 이전 보고서는 계속 읽을 수 있다.

독립 읽기 전용 리뷰에서 Critical/Important 지적은 없었다. 경미한 두 검증 공백도 보완해 Git 실행 파일 모드 100755와 gh 출력 초과·취소 시 실제 자식 종료를 검사했다. 추가 자체 점검에서 동기 어댑터 작업이 타이머 콜백을 지연시키면 기한을 넘겨도 수집이 완료될 수 있음을 재현했다. 각 읽기 전후·트리 확인·출처 증거 발급에 경과 기한 검사를 추가했다. 동기 호스트 코드를 강제 선점하는 기능은 아니며 기한 후 결과를 수용하지 않게 한다.

최종 로컬 검증: 기존 기준 일반 97/97 → 최종 **105/105**, 실제 Docker **9/9**, 생략 0. JavaScript·Bash 구문, YAML 파싱, diff 검사 통과. Git이 만든 합성 객체로 트리 정렬·일반/실행 모드·위조·누락·잘림·링크·인증 경로·공개 전환·main 이동·취소·기한을 검사했다. 합성 main 출처가 여섯 실제 npm 검사와 보고서로 연결됐고 출처 변조도 거부했다. 실제 비공개 main 점검은 별도의 blocked-capacity이며 게임 검사 통과 수에 포함하지 않는다.

# 대용량 기준·후보 독립 검증 v1

Phase 1의 다음 개발 단위다. PR #17의 기준 코드 한 단계 검사에, 암호화된 로컬 작업 결과의 후보 변경과 여섯 단계 비공개 보고서를 연결한다. `ai` 큐의 자동 실행·실제 모델 리뷰·게임 PR 게시 권한은 열지 않는다.

## 입력과 보존

`runLargeDiskIndependentChecks({id,stateRoot,privateKey,diskSnapshot,imageId,timeoutMs,outputLimit,signal})`는 검토한 로컬 호스트 코드에서만 호출한다. 데이터는 기본 민감 경로 정책을 통과한 checks 목적의 실제 디스크 수집/재열기 객체여야 한다. data-only·JSON 복사·위조 객체·Actions 호출은 claim/컨테이너 생성 전에 거부한다. 보관용 캐시를 실행용이나 의존성 준비용으로 자동 전환하지 않는다.

개인 키는 호스트에서 암호문을 여는 데만 사용하고 검사기에 전달하지 않는다. 작업 문맥·암호문 SHA·커밋·기존 bundle/manifest 검증을 통과한 후보 바이트를 불투명한 객체 안에 복사해 고정한다. 외부 객체를 나중에 바꿔도 각 검사는 같은 후보를 사용한다. `captureDiskCheckInput()`은 이 검토된 호스트 경계의 동기 입력 캡처 API이며, 임의 모델이나 runner 설정을 받지 않는다.

후보는 기존 PR 허용 경로의 TypeScript/새 테스트 1~8개, 파일당65,000바이트 제한을 유지한다. 디스크 실행 경로의 정규 형태·민감 디렉터리·길이240·깊이32 정책도 적용한다. 점(.) 경로 별칭으로 기존 테스트를 우회할 수 없다. 기존 test/spec 파일·test/tests/__tests__ 아래 테스트 덮어쓰기, 설정/package/lock 변경, 파일/디렉터리 충돌을 거부한다. 전체 기준+후보는10,000파일/1GiB 안이어야 한다. 파일 삭제·애셋 변경 허용 범위를 넓히지 않는다.

큰 원본 자료는 변경하지 않은 검증 tar 스트림으로 전달한다. 작은 후보는 별도의 이름 공간과 manifest를 가진 제한된 tar로 읽기 전용 입력 볼륨에 추가한다. 컨테이너 안에서만 기준 파일에 후보를 적용하고 기존 실행 모드를 유지한다. 자산·Unicode 이름과 전체 기준 트리를 생략하지 않는다. 호스트는 프로젝트나 설치 스크립트를 실행하지 않는다.

## 여섯 단계와 실패

기준과 후보 각각 타입 검사·전체 단위 테스트·빌드를 실행한다. 각 단계는 새 컨테이너·볼륨·프로젝트를 만들고 원본 blob의 크기·Git SHA1·SHA256을 다시 검사한다. 먼저 `npm ci --offline --no-audit --no-fund`를 실행하며 설치 스크립트를 생략하지 않는다. 이어 원래 명령을 실행한다.

1. 기준: `npm run typecheck`
2. 기준: `npm test -- --reporter=dot`
3. 기준: `npm run build`
4. 후보: `npm run typecheck`
5. 후보: `npm test -- --reporter=dot`
6. 후보: `npm run build`

네트워크·인증정보·호스트 소켓·자동 이미지 pull 없이 PR #17의 고정된 읽기 전용/nonroot/PID·CPU·메모리·tmpfs·시간·출력 제한을 유지한다. 다른 단계의 파일·node_modules·출력은 이어받지 않는다. 원본/후보 명령이 실패해도 여섯 결과를 비교하며 하나라도 실패하면 통과하지 않는다. 인프라/전송/취소 오류는 이후 실행을 중단하고 복구 필요로 남긴다. 정리 실패를 정상 검사로 승인하지 않는다.

신뢰된 로컬 호스트가 `runLargeDiskIndependentChecks({ ..., unitTestTimeoutMs: 900000 })`을 호출하면 두 전체 단위 테스트에 같은 15분 한도를 적용한다. 기본 한도는 7분이며 `timeoutMs`로 더 짧게 지정할 수 있다. 타입 검사·빌드·입력 전송은 기존 7분 상한을 적용한다. `unitTestTimeoutMs`는 100~900,000ms 정수만 허용하며 지정 값은 claim과 보고서에 기록한다.

전송 무결성·파일 권한·입력 펌프 오류 등 기존 보고서 열거형에 없는 저수준 실패는 `invalid_output`으로 정규화한다. 원시 오류·소스·작업 원문은 기록하지 않는다. 상세 비공개 진단 저장은 아직 별도 과제다. 기반 Docker 호스트와 cp 추출 성공 응답은 신뢰하며 동일 UID 악성 호스트/데몬은 기존 신뢰 경계 밖이다.

## 비공개 상태와 호환

작은 검사기와 **같은** independent-claim.json / independent-report.json 경로를 쓴다. 배타적 claim 한 개만 만들므로 서로 다른 프로필이나 동시 호출도 같은 작업을 중복 검증하거나 자동 재시도하지 못한다. claim 뒤 중단되어 보고서가 없으면 기존 running-or-needs-recovery 상태다. 마지막 로컬 상태/암호문 무결성 읽기에서 취소·변조를 발견하면 통과를 기록하지 않는다. 완료 보고서 추가가 확정 시점이다.

기존 schema1 보고서와 CLI는 유지한다. 새 보고서는 schemaVersion2/inputProfile=disk-v1이며 baselineManifestSha256와 별도의 후보 SHA를 묶는다. 이 manifest 지문은 기준 트리·파일 지문·수집 관찰을 담은 스냅샷 식별자이며 기존 baselineContentSha256라고 바꿔 부르지 않는다. main 출처는 수집 당시 관찰이고 현재 main 확인이나 서명된 게시 승인이 아니다.

schema2는 정확한 필드·문자열 타입·지문·출처·단계 순서를 검증한다. 배열을 문자열로 바꿔 이미지나 단계 정보로 인정하지 않는다. 관찰된 인프라 실패 뒤 실행 이력이나 다른 종료 원인을 넣은 모순된 복구 보고서를 거부한다. 기존 이미지 설정과 schema1 관찰의 문자열 타입도 강화하되 정상 이전 보고서는 유지한다.

모든 결과의 publishAuthorized는 false, review는 not-run이다. 여섯 단계가 통과해도 checks-passed-awaiting-review일 뿐이며 실제 모델 리뷰나 게시 허가를 뜻하지 않는다. CLI 실행/키 전달 기능은 추가하지 않았다.

```sh
node scripts/independent-check-cli.mjs status <task-id> <private-job-root>
```

## 검증과 다음 작업

합성40MiB Unicode 자산의 실제 Git 스냅샷과 암호화한 합성 작업 결과를 사용한다. 여섯 새 컨테이너에서 원본 자산 해시·변경 파일·npm ci 실행·단계별 lifecycle/단위 테스트 인자·이전 단계 오염 부재를 검사한다. 신뢰한 PID1 진입 인자의 요청 단계와 실제 lifecycle을 비교하며, 타입 검사/빌드 매핑을 임시로 뒤바꾸자 실패하는 것을 확인하고 원본을 복원했다. 실제 게임 TypeScript 검사·모델 리뷰 증거는 아니다.

경로 별칭/민감 디렉터리/길이/깊이, 실제10,000파일 한도, 기존 테스트 보호, 후보 바이트 고정, 보고서 변조·타입 혼동·모순된 복구 이력, 캐시 변조 뒤 읽을 수 있는 복구 보고서와 최종 읽기 도중 취소를 검사한다. 읽기 전용 리뷰의 중요 지적은 재현 테스트 후 수정했다. 리뷰어는 최종 전체 시험을 독립 재실행한 것이 아니다.

다음은 검증된 오프라인 의존성 런타임과 실제 실행 입력 정책이다. 기존 이미지는 실제 게임 의존성을 준비하지 않았으며 실제 게임의 기본 입력 정책 차단도 유지한다. 실제 게임 기준 검사·승인된 구독 AI 실행·독립 리뷰·키가 분리된 Draft 게시·모바일 배포는 미완료다. 이번에는 실제 비공개 게임 소스나 data-only 캐시를 실행/AI 전송하지 않았다.

최종 로컬 검증: 일반 **136/136**, 실제 Docker 합성 시험 **16/16**, 실패·생략0. JavaScript/Bash 구문·YAML·diff 검사도 통과했다. 새 모델 호출·실제 게임 검사·휴대폰 설치를 완료한 결과가 아니다.

후속 오프라인 npm 준비 기능은 이미 확보한 tarball을 검증해 이 여섯 단계에 공급한다. 실제 게임 의존성 수집과 실행 입력 검토가 남아 있다. [오프라인 npm 의존성 준비](offline-npm-runtime-v1.md)
